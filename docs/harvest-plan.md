# 收成预测 Demo 实施计划

目标：在现有侧栏新增收成预测，完成选地 → 作物/播期/投入 → 适宜性 → 产量与收益比较，可独立打开 harvest-demo.html 试用。

1. 不改变现有后端与租户数据。复用地块列表、Leaflet 地图和导航，计算代码单独模块化。
2. 气象：按坐标读取 Open-Meteo 2024 历史同期逐日均温、最低温、降雨和 ET0，最多 365 天（跨年到 2025）。这是历史情景，不是未来天气预报。示例模式使用人工构造的季节数据，必须主动选择，不默默兜底。
3. 适宜性：用透明、未标定的温度/霜冻、水量、pH/排水规则做初筛；缺少土壤地图、地类和海拔验证，不能确认真实地块可耕种。
4. 养分：将 AKILIMO R/quefts.R 数学核心移植为 JavaScript，保留 MIT 声明；土壤输入是季节有效 N/P/K 供应 kg/ha，不是传感器 mg/kg。木薯参数来自报告引用 Ezui et al. 2016；红薯使用报告中的马铃薯代理浓度参数，未标定，且原参数干鲜重基准需验证。
5. 产量上限使用自建气候折减情景，不冒充 LINTUL。默认潜在鲜重产量、干物质比例、价格均是假设，计算全程内部 kg/ha 干重，显示 kg/亩 鲜重。
6. 投入优化：枚举固定配比肥料候选 0–80 kg/亩，步长 5，预算约束针对新增肥料成本，风险偏好按低产情景比较收益。包含零投入候选，不声称全局最优。费用包含用户输入的每亩基础成本。
7. 验证：养分边界、零预算、面积换算、产量上限、冷害与涝害、输入无效、异步过期结果、浏览器交互。

验收：已有地块/示例地区/坐标/地图可选；更改输入后旧结果失效；断网仍可显式运行示例；输出原因、情景范围、三档投入对比和 JSON 导出。

后续：多年气候、国内土壤格网、红薯田间标定、真实肥料与收购价格、离线 LINTUL/WOFOST。独立 demo 无需登录且不读真实地块；正式侧栏沿用已有登录。

## 实施与验证记录

- 已实现侧栏集成与独立预览 `harvest-demo.html`；`harvest-model.js` 为可直接 Node 测试的计算核心。
- 历史接口使用 ERA5（实测 ERA5-Land 单独模式的降雨与 ET0 返回 null，已改用完整 ERA5 变量）。对缺失逐日值拒绝计算。
- `node --test tests/harvest-model.test.js`：6 项通过，覆盖模型边界、预算、面积/单位、天气风险、缺失值、零售价。
- 浏览器已验证海南红薯与哈尔滨木薯不同情景、参数切换清除旧结果、历史天气缺失提示。
- 启动完整平台：`node server.js`；侧栏进入「收成预测」。独立预览：`python3 -m http.server 3000 --bind 127.0.0.1`，打开 `http://127.0.0.1:3000/harvest-demo.html`。
- 最终浏览器验证：海口坐标 ERA5 2024-04-15 至 2024-09-11 共 150 天真实历史天气成功返回并完成试算；地图瓦片与结果布局正常。已对新增静态资源加版本号，避免修改后沿用旧缓存。
