# AI收成预测 Beta 4：算法、参数来源与数据缺口

实现：`harvest-model.js`（纯计算）、`harvest.js`（界面）、`scripts/diagnose-harvest.js`（逐年诊断）、`scripts/calibrate-harvest.js`（离线校准）。
算法 `harvest-beta-4.0.0`，参数 `tubers-beta-2026-09-28`。仍为 Beta：红薯、木薯均**没有地区或品种实测校准**。本文取代 `harvest-algorithm-v3.md` 中的生长、水分与评分部分。

> 公式更复杂不等于更准确。本版解决的是“结构性错误让结果失真”，没有与实收数据比较误差，不能声称精度提高。

## 1. 诊断：为什么旧版各年结果几乎相同

用 ERA5 实测天气（Open-Meteo，2015–2025）逐年运行旧版 3.1.0，供水“充足”，排水“良好”：

| 情景 | 旧版鲜薯 kg/亩（10年） | 不同数值 | 原因 |
|---|---|---|---|
| 海口 红薯 4/15 | 2347–2400 | 2 | 9/10 年 `clamp(growth)=1`，撞到 `潜力36000 kg/ha × 干物率` 的统一上限 |
| 海口 木薯 3/15 | 2040（全部相同） | 1 | 10/10 年被 QUEFTS 养分限制，气候差异被完全抹平，页面没有说明 |
| 南宁 红薯 4/15 排水较差 | 1841–2288 | 10 | 只按“当天排水>5mm 生长×0.65”，约1100mm雨季几乎不减产 |
| 潍坊 红薯 8/1 | 542–889 | 10 | 大量≤0℃ 日，但总评分直接为0，没有区分冷害与冻害 |

确认的四个结构问题：

1. `progress` 到1后 `step=0`：之后的天气完全不再影响产量（木薯尤其不合理）。
2. `potentialDry × clamp(growth)`：好年份都撞到同一上限。
3. 超过田间持水量的水当天全部排走，没有持续积水状态。
4. `evaluateClimate` 的总分漏了 `wetGrowthLoss`，完整分析与仅气候分析同一气候得分不同。

复现：`node scripts/diagnose-harvest.js weather.json 2026-04-15 sweetpotato unknown`（weather.json 为 Open-Meteo archive 返回，含六个逐日变量）。脚本逐年打印温度、辐射、降雨、补灌、冷害/冻害风险天、高温天、过湿天、阶段、叶面积、累计生物量、气候/pH/养分限制前后产量、收入、成本、利润，以及 `NUTRIENT` / `CALIB-CAP` / `IMPLAUSIBLE` 截断标记。

## 2. 逐日生长：简化的光能利用模型（参考 LINTUL 结构）

单位：辐射 MJ m⁻² d⁻¹；PAR = 0.5 × 短波；干物质 g m⁻²（×10 = kg/ha）；叶面积指数 LAI m² m⁻²；水 mm。

```
每日干物质 = RUE × PAR × (1 − e^(−k·LAI)) × fT × min(Ks, Kw)
```

- **截获辐射随冠层变化**：幼苗期（积温进度<0.3 且 LAI<0.75）LAI 按积温指数增长；之后 LAI 由新增叶片干重 × 比叶面积决定；衰老 = 年龄衰老 + LAI>4 的遮荫衰老 + 冷害/冻害损伤。
- **生育进度只决定阶段、Kc、根深与分配**，不直接决定每日新增量。先分出纤维根，其余按进度分给叶、茎蔓、块根。
- **进度可以超过1**：红薯超过参考积温后衰老加快，但只要仍有叶片就继续积累；木薯为持续生长作物（DSSAT MANIHOT 同样没有固定终点），后期分配保持，按计划收获日结束。
- 块根干重 ÷ 干物率 = 鲜重；kg/ha ÷ 15 = kg/亩。
- 取消统一的潜在产量硬上限。保留**合理性检查**：超过参数表中的鲜重量级时标记 `implausible`，不截断。
- 校准包仍不能超过气候与pH限制产量，被截断时标记 `calibrationCapped`。

这**不是完整 LINTUL**：没有分层根系吸水、呼吸、氮动态和品种物候。RUE、消光系数、比叶面积、分配表均为未标定假设（见参数表）。

**绝对产量水平需要警惕**：海口4月红薯的气候限制产量约 2470–3550 kg鲜薯/亩（37–53 t/ha）。这是充分灌溉、无病虫害、未扣养分时的模型值，明显高于 EcoCrop 记载的一般“最佳产量 17.5–27.5 t/ha”。它适合在同一套参数内比较年份、播期和地点，还不能当作当地实收预期；目前红薯养分参数又是马铃薯代理，偏宽松。需要实收数据校准。

## 3. 温度：四种机制分开

| 机制 | 输入 | 计算 | 对产量的作用 |
|---|---|---|---|
| 生长温度 | 日最高、最低温 → 余弦曲线估计逐时温度 | 日间（6–18时）逐时温度的连续梯形响应（最低/适宜下限/适宜上限/最高） | 乘到 RUE 上 |
| 冷害 | 日最低温 < 冷害阈值（红薯10℃，EcoCrop） | 冷害剂量 = 逐时 (阈值−T) 的日均值，建立期×1.5 | 增加叶片死亡（系数为假设） |
| 叶片受冻 | 日最低气温 ≤ 0℃ | 叶片损失 = min(0.9, 0.3 + 0.2×(0−Tmin)) | 只损伤叶片，**一次≤0℃不等于整株死亡**；2m气温不能证明实际结霜 |
| 植株死亡 | 日最低 ≤ −2℃，或日均温持续偏低（红薯≤3℃连续3天；木薯≤5℃连续5天） | 死亡后停止生长、叶片清零 | 阈值为假设，待确认 |
| 地下部受损 | 膨大期持续冷害/≤0℃，或植株死亡后块根留在田里 | **未建模**：不计算损失，也不默认块根全部可销售 | 触发即限制可行性结论 |
| 高温 | 日最高温 ≥ 35℃（红薯，CIP 生长范围上限） | 统计高温天与高温小时 | 只作暴露指标；高温对光合的影响已在连续响应中，不重复扣分 |

用逐时温度而不是日均温，所以“白天40℃、夜里14℃”不会被平均成“27℃适宜”（有回归测试）。缺日最高温时，用 `2×均温−最低温` 估计并标记 `tmaxEstimated`，高温暴露显示为未评估。日夜温差、热夜效应暂无参数依据，没有加入。

## 4. 水分：供水假设与过湿风险分开

根区可用水 `TAW = 1000×(FC−WP)×根深`，另有田间持水量以上的暂存空间 `1000×(SAT−FC)×根深` 和地表积水。每日顺序：

1. 根系加深带入的新土层水；
2. 积水 + 降雨按 Ksat 入渗，受饱和剩余空间限制；
3. 超过地表蓄水能力的部分成为径流，沟渠每天再排走一定比例的积水；
4. 补灌（只在无积水时，补到 FC 以内）；
5. 深层排水 = min(τ × 超出FC的水, 出口排水上限)，τ 按 AquaCrop 关系由 Ksat 估计；
6. 蒸散先耗积水，再耗土壤水，缺水系数 Ks 按 FAO-56。

质量守恒：`初始水 + 新根层水 + 降雨 + 灌溉 − 径流 − 排水 − 蒸散 − 期末土壤水 − 期末积水 = 0`，所有质地×排水×供水组合的测试误差 <1e-6 mm。

**过湿**：有积水，或超出FC的水达到饱和余量的一半，记为缺氧日。连续缺氧天数 `run`（非缺氧日每天减1，恢复需要时间），第1天不减产；`Kw = 1 − 0.8×(1−e^(−(run−1)/2))`；块根膨大阶段连续缺氧超过3天，每天损失块根的 `2%×强度`。单日暴雨若及时排走基本不影响；多日积水影响显著（有测试）。所有系数为假设。

**排水情景**：默认“不确定”——主结果按“一般”，模型同时计算“良好/一般/较差”三种情景（导出 JSON 中保留）；页面只在较差排水会让产量低 10% 以上时，在“过湿与排水”里提示一句。例：南宁4月红薯，气候限制产量良好 2376 / 一般 2373 / 较差 413 kg/亩（较差情景平均缺氧77天）。旧版的“较差”几乎不减产。

**洪水**：只模拟降雨导致的田间过湿与积水。没有地形、河网、洪水资料，河流洪水淹没在界面上明确显示为“尚未评估”。

**供水**：默认“按及时灌溉计算”，不再有“浇水100分”评分卡；页面显示平均预计补灌量。选择“只靠降雨/有限补灌”时才出现“水分供应”一项。

## 5. 能不能种：逐季可行性判断（feasibility）

“分数尚可”不等于“可以种”。模型对**每个历史生长季**单独检查，再汇总成四种状态之一；界面标题只显示这个结论：

| 状态 | 条件（汇总阈值为Beta政策，见参数表 `feasibilityPolicy`） |
|---|---|
| 所选季节条件支持种植 | 所有年份各项检查通过，且没有未建模的严重低温风险、没有明显持续过湿 |
| 有明显风险，需调整方案 | 任一年不满足；或 ≥30% 年份处于边缘；或任一年有未建模的严重低温风险；或过湿对照指标 <60 |
| 不建议按当前露地方案种植 | ≥30% 年份不满足 |
| 数据不足，无法判断 | 人工天气情景；或完整历史生长季少于3个 |

每季的检查（红薯、木薯分别设参数；品种未确认时使用Beta区间，低于区间下限＝不满足，区间内＝边缘）：

1. **建立期成活**：前21天（木薯30天）平均气温与区间比较；期间出现≤0℃直接不满足。
2. **连续适温窗口**：5日滑动平均气温≥阈值的最长连续天数（红薯≥15℃需90–120天；木薯≥16℃需180–240天）。
3. **计划收获前的低温**：植株死亡（见第3节）发生在计划收获前，则检查死亡前一天是否已满足可收获条件——满足则为“边缘，须提前N天收获”，否则不满足；同时标记“地下部低温：未建模”。没有死亡但膨大期持续冷害或≤0℃，也标记为未建模风险。叶片受冻单列为边缘，不等于死亡。
4. **可收获条件**：按有效积温和生育天数的品种区间判断，而不是“产生了块根就算可收”。木薯没有固定成熟终点，但生长期不足时同样判为不满足。

页面上：所有年份都通过时不再单独显示判断依据（结论已在右侧“地块分析”）；有风险、不建议或数据不足时显示“需要注意的问题”，把每项检查换成大白话（如“收获前会遇到严重低温，植株可能冻死：10/10 年”），逐年明细和汇总规则默认收起。年景产量图只在各年产量相差 ≥3% 时显示。

输出包含 `years[]`（每年 verdict 与每项检查的原因）、`passYears / marginalYears / failYears` 和按检查项汇总的原因。**相对产量分数保留作解释，不参与这个判断。**模型不再在生育期偏短时给出“可考虑延长生育期”的建议：延长需要重新计算，并检查是否进入寒冷季节。

同一规则适用于任何坐标，没有城市特判。实测天气（2015–2025 ERA5）下的例子：

| 地点 · 作物 · 播期 · 天数 | 结论 | 主要原因 |
|---|---|---|
| 海口 红薯 4/15 · 150 | 支持 | 10/10 年通过 |
| 海口 红薯 9/27 · 150 | 有明显风险 | 部分年份冬季适温窗口/积温处于边缘 |
| 潍坊 红薯 4/15 · 150 | 有明显风险 | 4/10 年建立期气温处于边缘 |
| 潍坊 红薯 5/10 · 150（适季） | 支持 | 10/10 年通过 |
| 潍坊 红薯 8/1 · 150（跨入冬季） | 不建议 | 10/10 年收获前达到植株死亡条件，此前积温不足；地下部受损未建模 |
| 潍坊 木薯 4/20 · 300 或 180 | 不建议 | 适温窗口不足，入冬前达到死亡条件 |
| 海口 木薯 3/15 · 300 | 支持 | 10/10 年通过 |
| 南宁 木薯 3/15 · 300 | 有明显风险 | 2/10 年适温窗口处于边缘或有低温风险 |

## 5b. 是什么限制了生长（解释指标）

统一由 `assess()` 计算，完整分析与仅气候分析共用同一函数（测试确认同一气候的三项因素完全相同）。

| ID | 名称 | 分数含义 |
|---|---|---|
| `temperature` | 温度适宜性 | 实际模拟 ÷ 关闭温度限制（含冷害、冻害；发育速度不低于适温区间中点）的对照模拟 |
| `light` | 光照条件 | 实际 ÷ 全季 FAO-56 晴空辐射对照；晴空是理想上限，所以档位为 70/50 |
| `wetness` | 过湿与排水 | 实际 ÷ 关闭过湿缺氧影响的对照；风险提示含“河流洪水：尚未评估” |
| `water` | 水分供应 | 仅在非默认供水时出现 |
| `ph` | 土壤酸碱度 | pH 响应规则；未提供为 `null` |
| `nutrients` | 养分供应 | 较优施肥方案下 QUEFTS 后 ÷ 养分前；另输出 `fertilizerNeed`：按带走量（红薯 EcoCrop 每吨鲜薯 4/1/7 kg N/P/K；木薯广西农业农村厅 3.5/0.75/6.2 kg）减土壤供应，给出“施肥需求 较多/中等/较少”和每亩 N、P₂O₅、K₂O 缺口，未计肥料利用率，不是处方；未提供为 `null` |

每项包含 `id、status(favorable/moderate/unfavorable/unknown)、score、evidence、metrics(原始指标)、method、source、assumption、risks`。未知一律 `null`，不用0或100代替。

- **气候条件分**：实际 ÷ 同时关闭温度、过湿、缺水限制的联合对照（不是各项相加或相乘）。光照是资源量，不计入气候条件分，单列。
- **种植条件分（含土壤）**：min(气候条件分, pH, 养分)；任一缺失则为 `null`。
- **收获时发育状态**另列，不计分。
- **单因素对照增量**：仅去掉某一因素后的块根增加量，注明“因素之间有交互，不能直接相加”。
- 分数是模型指标，不是成功概率，也不是实测减产比例。界面只读取结果，不修改模型对象（有测试比对渲染前后JSON）。

## 6. 逐年产量与收益

每个历史年份：气候限制块根干重 → × pH 系数 → QUEFTS 养分限制 → 鲜重 → × 商品率 → 收入。成本：基础成本 + 新增肥料 + 按产量的采收运输费 + **灌溉费（仅在填写单价时，按模拟补灌量，1 mm = 0.667 m³/亩）**。未填写单价时注明“灌溉费用未计入利润”，不编造电价、水价或历年农产品价格。

- 各年使用相同售价和基础成本，这是对比假设，页面写明。
- 如果多数年份被养分限制、养分后差异小于气候差异一半，结果中给出解释（例：海口木薯，气候产量相差约19%，养分后完全相同）。
- 历史情景 P10–P90 不是未来预测置信区间；亏损年份占比不是已校准的未来亏损概率。

## 6b. 土壤剩余可用水与灌溉费用

**逐日水量**（界面“土壤剩余可用水与浇水需求”）只读取 `simulateSeason().trace`，前端不另算水量。每天输出并区分：

| 字段 | 含义 | 单位 |
|---|---|---|
| `available` | 根区剩余可用水，限制在 0–`capacity` | mm |
| `availableFraction` | 根区可用水比例，分母为当天根区容量 `capacity`（随根深变化） | 0–1 |
| `excess` | 超出田间持水量的过湿暂存水（`storage − capacity`，不计入可用水） | mm |
| `pond` | 地表积水 | mm |
| `rain / irrigation / et / runoff / drainage / newRootWater` | 当天降雨、补灌、蒸散、径流、深层排水、根系加深带入的新土层水 | mm |

日水量账：`前一天(土壤水＋积水) ＋ 新根层水 ＋ 降雨 ＋ 补灌 − 蒸散 − 径流 − 深层排水 = 当天(土壤水＋积水)`，测试逐日核对，且逐日补灌之和等于整季补灌。这是所选历史天气情景的模拟值，不是今天的实测含水量；根区加深会改变容量，曲线变化不全来自降雨或浇水。图表上方为可用水比例（0–100%），下方为带 mm 刻度的降雨、补灌和“过湿暂存水＋积水”子图，刻度最大值写在图上，不再截平。可切换年景并用拖动、点击或方向键查看某一天，这些操作不会重新请求天气或重跑模拟。

**灌溉费用**（`output.water`，完整分析和仅气候分析都有）：

- 单价口径：每立方米到田补灌水的综合费用（抽水电费、水费等）。模型给的是到田水量，没有另外加输配水损耗，避免重复计算。
- 换算：1 mm ≈ 0.667 立方米/亩 = 10 立方米/公顷；整块地按面积汇总。单位切换只改显示，不改底层计算。
- 单价留空时费用为 `null`，显示“未计入”，不显示成 0 元；填 0 才是真实的 0 元。
- 界面默认填入 0.5 元/立方米作为**粗略参考值**（国内水费加抽水电费，常见约 0.2–1 元，取决于水源、扬程和电价）。用户没改过时，结果会标出“单价是粗略参考值，不是当地实际水电价”（`water.priceOrigin = 'example'`）；换成其他币种时自动清空，不套用人民币参考值。
- 勾选“基础成本已包含灌溉费”时不再单独扣除，逐年差额只作说明；否则按年扣除一次（有测试核对利润只扣一次）。
- 参考值固定为：同一地块、作物、播期与管理方案下，所选完整历史生长季的平均补灌量和平均灌溉费，文案写“相对所选历史年景平均值”，不叫“正常年份”，也不是未来预测。
- 页面示例：“2020 年景需要多补灌 143.8 立方米/亩，灌溉费比历史情景平均值增加 115 CNY/亩。”并说明：及时灌溉可以减轻缺水对产量的影响，但会增加投入。

**土地与施肥的边界**：土壤质地和排水已经通过持水量、排水速度和过湿影响补灌量与生长，不另加“土地费用”。自然深层排水不是水泵排水，不按它收费。施肥量不进入水量账；在没有可信的养分淋失模型之前，不按降雨自动追加补肥费用。排水设施和补肥费用等有数据后再扩展。

## 6c. 施肥方案、成本卡片与 2026 年肥料参考价

**红薯养分参数（2026-09-29 更正）**：原先借用的“马铃薯代理”浓度值折算后，每 kg 吸收氮可产约 175–435 kg 块根干物质，比红薯文献高 3–5 倍，模型因此以为几乎不需要施肥。现改用 Kumar 等 2016（印度多点试验）的红薯 QUEFTS 参数：最大富集 a = N 40 / P 96 / K 30，最大稀释 d = N 80 / P 272 / K 85（kg 块根 / kg 吸收养分）；平衡吸收时每吨块根约需 16 kg N、6 kg P、18 kg K。原文未能访问，按干重口径使用：折算为鲜重（干物率 25%）约 4 / 1.5 / 4.5 kg，与 EcoCrop 每吨鲜薯带走 4 / 1 / 7 kg 基本一致。仍是印度参数，未做中国品种标定。

**推荐施肥（`output.plan`）按收益选**：从不施肥开始，每一步尝试加 5 kg 复合肥（15-15-15）、1 kg 尿素、2 kg 钾肥（红薯硫酸钾，忌氯；木薯氯化钾），或三者各加一步，选让目标（稳妥＝较差年份利润，均衡＝平均利润）增加最多的一步，直到再加也不多赚为止。约束：
- 肥料预算（默认改为 500 元/亩）；
- **常见用量上限**（参数表 `fertilizerCaps`）：红薯复合肥 100、尿素 10、硫酸钾 30 kg/亩；木薯复合肥 80、尿素 35、氯化钾 25 kg/亩，约为广西农业农村厅常见用量的 1.3–2 倍。设上限是因为模型产量潜力未标定、偏高，不加上限时“收益最高”会给出每亩数百公斤、800 多元的不合理用量。

如果施肥比不施肥多赚不到 3%（或每亩不到 30 元），推荐不另施肥。比较表列出不施肥、推荐量的一半、推荐量；只有推荐量在上限和预算以内（内部最优）时，才另列“推荐量的 1.5 倍”，用来说明再多施已不划算。海口 3 月种红薯（手填土壤 60/12/80）推荐复合肥 100 kg、尿素 10 kg、硫酸钾 30 kg/亩，约 486 元/亩，达到上限；木薯推荐复合肥 80、尿素 35、氯化钾 24 kg/亩，约 422 元/亩。

**为什么施肥后各年产量接近**：年景图每年画两根柱子：天气能支撑的产量（不计养分）和推荐施肥后的产量。当各年天气潜力都高于养分能支撑的产量时，最终产量被养分封顶而接近相同，这是 QUEFTS 养分限制的正常结果，页面会写明。

**国内土壤换算（2026-09-29）**：国内格网只有 0–4.5 cm 表层。整季供应改为按 0–20 cm 耕层估算（假设表层浓度代表整个耕层，对应常见测土取样深度）：浓度 × 容重 × 20 cm × 假设利用比例（N 0.3、P 0.2、K 0.4），约为原来只按 4.5 cm 算的 4.4 倍；`soilSupply(data, fractions, {depthCm:null})` 仍可只用实测表层。点位无数据（城区、水面）时沿用最近的有值格点。格网是约 1 km 的历史背景值，不区分是否农田，也不能代替地块测土。

**设置精简**：删除“肥料配方与用量范围”（推荐施肥已按常用肥料和用量上限自动计算）和“地区校准包”（目前没有可用的包；模型接口仍保留校准校验）。

**价格**：2026-09-11 生意社化肥基准价（尿素 1.81、复合肥 15-15-15 3.49、硫酸钾 3.95、氯化钾 3.33 元/kg），复合肥单价取输入框（默认 3.49）。基准价是市场批发价，农户买价通常更高。“常用肥料与 2026 年参考价”默认收起，放在“比较不同施肥量”（默认展开）下面。

**预计成本**卡片在“预计能赚多少钱”下方，全部按平均每亩（或每公顷）：基础成本、肥料（推荐方案）、灌溉用水（默认参考单价 0.5 元/立方米）、采收运输及合计，不再显示整块地合计。

## 7. 播期比较

**先检查可行性，再排序**：只有“支持种植”的候选参与按产量排序；全部候选都不通过时，输出“未找到合适的露地种植窗口”，界面上把当前显示的日期标为“相对较好的试验方案，不是推荐种植方案”。同样的历史年份、供水、排水和生育期；目标名称明确为“平均气候限制产量（养分前）”，同时报告较差年份 P10，并做**逐年留出**检验（每次去掉一年重新排序，报告首选日期保持第一的比例）。这是平均值目标，不称为风险最优。

## 8. 天气数据检查

逐日均温、最低温、最高温、短波辐射、降水、ET0 六个变量按日历日期对齐。任一变量缺一天，整个年景排除并写明原因；不补0，不补理想光照。辐射须在 0–45 MJ/m²/日且不高于当日大气顶辐射（用来发现把 W/m² 当 MJ 的单位错误）。没有辐射时不能计算产量，仅气候分析里光照显示“未评估”。湿度/VPD、风、台风和病害列为后续模块，本版不扣分。

## 10. 校准与版本

- 校准包必须匹配 `harvest-beta-4.0.0` / `tubers-beta-2026-09-28`；3.x 的包一律拒绝（有测试），不会静默沿用。
- `scripts/calibrate-harvest.js` 规则不变：按地块和年份划分训练/验证，验证年份晚于全部训练年份，不随机拆同一地块；只拟合整体偏差；输出永远是 `candidate`。
- 后续应按“地区 × 品种”建立参数包（RUE、分配表、干物率、温度阈值、排水情景），保留版本号；与旧模型在同一独立验证集上比较 MAE/RMSE/偏差后，才能声称精度改善。

## 11. 仍缺的数据

| 用途 | 需要收集 |
|---|---|
| 生长参数标定 | 品种、种植/收获日期、密度；分期测定的叶面积或冠层覆盖、生物量、块根干重与干物率 |
| 水分与过湿 | 分土层质地、田间持水量、饱和含水量、渗透/排水能力、地下水位；起垄高度与沟渠；**实际积水日期与持续时长** |
| 土壤化学 | 分层 pH、有效 N/P/K（注明提取方法）、容重、采样深度与日期；缺素对照试验。化验浓度不能直接当整季可吸收供应 |
| 管理 | 实际灌溉日期与水量、施肥产品/用量/日期 |
| 验证与收益 | 实收鲜重、商品率、分级售价、各项成本（含灌溉水电单价） |
| 其他风险模块 | 地形/DEM、河网与历史洪水范围、极端风/台风、病虫害记录 |

旧的国内表层背景土壤（0–4.5cm，约1km）与未来可能接入的海外估算（iSDAsoil/SoilGrids）都必须在结果里注明来源和不确定性；本版没有为海外地点生成任何养分或产量。

## 12. 验证范围

`npm test` 中收成相关测试覆盖：结果可复现且无随机项；养分不主导时辐射、低温、高温改变产量；日夜温差不被平均为适宜；8℃为低温限制与冷害风险而非霜冻；充分灌溉消除缺水但不消除持续积水；多日积水与单日及时排水不同且水量守恒；木薯过参考积温后继续增长；完整/仅气候分析气候因素一致；缺数据显示未知而非满分；辐射单位与日期错位被拒绝；排水未知给出情景；灌溉费仅在有单价时计入；养分瓶颈时给出解释；无统一硬上限；播期比较带留出检验；旧校准包被拒；每个参数都有单位、来源与可信度；界面不修改模型结果；重复提交与快速换地点不串结果（原有测试保留）。

`tests/harvest-feasibility.test.js` 另覆盖：温暖年份判为支持；人工天气和不足3季判为数据不足；气候分≥85但生育期过短仍判为不建议；一次≤0℃只伤叶、−4℃才判植株死亡；膨大期低温标记地下部未建模风险并限制结论；入冬前死亡判为不建议并给出年份和原因；单个坏年份按年份列出而不被平均掉；木薯短生育期不可收；同一天气在不同坐标结论相同；播期先检查可行性再排序，全部不通过时明确无合适窗口；不给未检查的延长生育期建议；界面标题来自可行性结论而非分数。

`tests/harvest-water.test.js` 覆盖：逐日水量账闭合、逐日补灌之和等于整季、可用水/过湿暂存水/积水拆分；单位换算与相对平均值的差额；空单价与 0 元区分；利润只扣一次灌溉费，已含在基础成本时不再扣；仅气候分析也显示用水与费用但不生成产量；查看某一天不调用模型；按公顷和整块地汇总正确。

测试通过只说明实现符合这些约束，**不等于田间精度验证**。
