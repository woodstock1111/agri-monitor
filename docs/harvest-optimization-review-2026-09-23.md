# AI收成预测优化评估与数据清单

日期：2026-09-23。范围：本地工作区中的收成预测模块及其接入点。此次只做审查、资料检索和方案整理，不修改运行代码、不部署。

用户补充：暂不确定重点品种；已有海外使用者，希望兼顾非洲与东南亚。产品不先限制为某一个地区；保留现有中国能力，以全球天气和分地区土壤来源扩展，缺少养分时仍可输出有依据的气候分析。

## 0. 非洲与东南亚接入路线

国外数据并非找不到。已经查到官方资料和访问方式，但本次未进行海外点位实际取值、数据下载或账号注册，数据接入与农艺标定仍是两项不同工作。

| 区域/层次 | 候选来源 | 能支持的功能 | 仍缺什么 |
|---|---|---|---|
| 中国、非洲、东南亚天气 | Open-Meteo / ERA5全球历史天气 | 多年温度、雨量、ET0、辐射及季节风险 | 当地站点校验；不能把历史天气当未来实况 |
| 中国土壤 | 已有中国格网；后续评估CSDLv2或近期测土 | 现有表层背景查询继续可用 | 深层与近期实测、地区参数 |
| 非洲土壤 | iSDAsoil，多数土壤层30m，0–20与20–50cm | pH、质地、容重、有机碳、全氮，以及Mehlich-3提取磷/钾和不确定性 | 全氮不是整季有效氮；提取法不能直接套中国有效养分转换；水域/沙漠等无覆盖 |
| 东南亚及全球基础土壤 | SoilGrids，250m、六个标准深度层 | pH、质地、容重、有机碳、全氮等基础属性，供适宜性与水分模块使用 | 不提供当前算法所需的一套有效N/P/K；施肥预测需本地测土/试验补足 |

iSDA官方提供注册后使用的免费API，也提供公开AWS栅格。建议先用样点核验API/栅格的层名、单位、深度与返回结果，再按目标国家/地块区域裁剪缓存，避免整块大陆全量下载。[开发者文档](https://www.isda-africa.com/isdasoil/developer/)、[属性与检测方法](https://www.isda-africa.com/isdasoil/faq/)。部分栅格数值需要反变换，需严格按元数据处理；API与批量栅格的属性清单也应分别核实。[AWS访问说明](https://www.isda-africa.com/isdasoil/isdasoil-on-aws/)

SoilGrids官方当前公告REST API暂停且无恢复时间，应使用官方文件/区域裁剪与缓存方案，不把在线REST接口作为唯一生产依赖。其基础属性缺少有效磷/钾，不得用全氮或固定NPK冒充完整施肥输入。[官方属性与服务状态](https://isric.org/explore/soilgrids)

分级输出规则：只有天气时，输出气候初筛；有基础土壤时，补土壤/水分条件；有可用的养分供应估计及作物参数时，才进入带明确假设的产量情景；有当地成本与售价时，再输出当地货币的收益比较。无数据要显示“待补充”，不能显示为“不适合”。

国际化UI补充：自动识别地区并显示实际数据来源；单位支持亩/公顷、kg/吨，价格使用明确币种并由当地用户输入；不把人民币默认价格平移到其他国家。种植日期使用当地日期，标签优先“种植/移栽日期”。品种可以暂时未知，但必须显示正在使用通用参数，保存后允许补填。

标定可以从用户真实记录最多的国家/作物组合开始；这不限制其他地区访问基础功能。样本按国家、农生态区、作物、品种和种植季分组，不能把中国、非洲、东南亚混合后宣称统一准确率。

| P1 | 只有15-15-15，0–80kg/亩、步长5；不能比较不同配方 | 支持当地实际肥料产品、N–P₂O₅–K₂O配比、单价、施用成本和分次施肥；保留零新增投入基准 | 产品标签/报价、已有施肥、当地试验或农技约束 |

| P1 | 浏览器每次直接拉天气；土壤相邻坐标可能重复启动Python | 天气按格点和日期缓存；土壤按实际格网索引缓存，合并同时查询；常驻读取器由性能测量决定 | 不需农艺数据；需与后端worker协调 |
| P2 | 没有实收反馈和独立验证流程 | 保存模型/参数/数据版本与预测时点，关联季末实收；按地块与年份划分验证集 | 真实生产记录 |

可复现例子：150天、均温26℃、最低温19℃、ET0每天3mm，其余参数相同。

- 每天4mm降雨，与前10天每天60mm、后140天零降雨，当前模型输出完全一致，例子中都是2400kg/亩。说明水分模块不能识别连续干旱，而非证明任何一个结果是真实产量。
- N/P/K供应都为0且新增肥料预算为0，当前模型可输出规则评分100、产量0。气候评分本身可以较高，但页面必须明确与养分/产量分开。

## 3. 推荐的算法结构

1. 地块与数据检查：坐标系、真实种植边界、日期、来源、单位、缺失字段。
2. 作物参数：按作物、地区和品种维护参数集，逐步确定生育阶段、积温、根深、干物率和养分效率；允许品种未知，展示通用参数的适用限制。
3. 气候情景：多年逐日天气逐季运行；不把一整季都当作可预报天气。
4. 水分与产量上限：先改进轻量逐日水量平衡。光照驱动生物量、完整LINTUL/WOFOST接入作为有参数与验证数据后的后续工作。
5. 养分：保留可测试的QUEFTS核心，替换经过审核的作物参数，并用本地试验标定土壤供应和施肥响应。
6. 经济比较：在明确候选、预算与农艺约束下比较增量收益；当前生产方案作为基准。
7. 结果：分别报告限制因素、历史情景产量分布、经济情景和数据来源。历史P10/P50/P90只代表所选历史情景分位数，不自动等于未来产量置信区间。

FAO-56给出了按日根区水量平衡、田间持水量/萎蔫点、根深与水分胁迫的计算框架，可作水分模块依据；仍须校准作物系数与生育阶段。[FAO-56第8章](https://www.fao.org/4/X0490E/x0490e0e.htm)

已找到甘薯专用研究：Kumar等，2016，*Application of QUEFTS Model for Site-Specific Nutrient Management of NPK in Sweet Potato*，DOI 10.1080/00103624.2016.1194989。它是候选参数来源，不是中国品种已验证参数；本次确认了论文与研究对象，尚未完成完整参数表复核。[研究论文](https://doi.org/10.1080/00103624.2016.1194989)

## 4. UI/UX建议

| 当前体验 | 建议 |
|---|---|
| 首屏是很长的表单，已有地块排在示例后 | 首先显示“我的地块”，示例另列；地点、作物/品种、播期、面积作为首轮基本输入 |
| 普通用户需要理解kg/ha供应量与利用比例 | 增加“录入测土报告”：填写报告原始单位、采样深度、日期和方法；模型参数放到专业设置 |
| 土壤、天气、默认值混在一起 | 显示三个状态：土壤已读取/待补充、天气年段、品种参数来源；缺数据只影响对应结论，不把无数据算成不适宜 |
| 100分和候选最优容易被理解为确定答案 | 顶部用“主要限制因素＋下一步行动”；亩产、全地块可售总量、收益分开展示；注明场景范围与实际验证情况 |
| 修改输入会直接清空旧结果 | 保留旧结果并标记“参数已修改，待重新计算”；新增方案A/B对比，不能让旧结果冒充新结果 |
| 手机需滚动穿过全部输入才能看结果 | 分为地块、种植计划、结果三步；底部固定主按钮，结果生成后定位到摘要 |
| 小字号提示很多，方法说明默认全部展开 | 关键事实在结果附近简短显示，方法细节折叠；提升移动端字号、对比度与点击区域 |
| 只能导出JSON | 增加可打印的简报和“录入实际收获”；保留机器可读JSON用于复算 |

建议的结果顺序：主要风险 → 亩产及总量 → 当前方案/备选方案收益比较 → 数据完整性与依据 → 补数据/录实收。

## 5. 目前算法实际需要哪些输入

- 地理/种植：经纬度、作物、播种日期、生育天数、面积（亩）。坐标和播期主要用于选择数据；当前评分没有地类或坡度检查。
- 气象：每天均温、最低温（℃）、降水（mm）、ET0（mm）。
- 土壤：pH及整季N/P/K供应（kg/ha，元素基准）。国内模式由AN/AP/AK（mg/kg）、容重（g/cm³）、土层厚度和假设利用比例换算。有机质当前只展示，没有参与产量计算。
- 管理：雨养/灌溉充足假设、排水好/差。
- 经济：肥料预算（元/亩）、肥价（元/kg）、鲜薯价（元/kg）、基础成本（元/亩）、风险偏好。
- 内置参数：品种缺省的潜在产量、收获指数、干物率、温度阈值、植株养分浓度边界与施肥回收率。目前固定写在代码中。

## 6. 建议收集的数据：按价值排序

| 优先级 | 数据与必要字段 | 用途 | 获取方式 |
|---|---|---|---|
| 第一批 | 地块ID、WGS84坐标/边界、面积及单位、海拔/坡度、作物、品种、前茬、播种和收获日期、密度 | 把天气、测土、管理、实收关联为一季样本 | 自有地块资料、种植户台账；明确地图坐标系再转换 |
| 第一批 | 实收鲜重kg、实收面积、商品薯重量/分级、异常损失；记录是整田过磅还是抽样估算 | 标定亩产、商品率和误差，作为独立验证的真值 | 收购过磅单、收获台账、规范田间测产 |
| 第一批 | 每次肥料产品、N/P₂O₅/K₂O标签、实际施用kg、日期、施法、单价；有机肥另记含水率/养分分析 | 标定投入响应；避免已有投入与新增肥料重复计算 | 农事记录、包装照片、购肥单；不能只记“施肥一次” |
| 第一批 | 土壤采样日期、上下层深度cm、pH、碱解氮/矿质氮的具体项目、有效磷、速效/交换性钾mg/kg、有机质或有机碳g/kg、容重g/cm³、检测方法与实验室 | 建立测土与整季养分供应关系 | 有资质的测土机构、合作农科院、农技站。先取实际耕层，如0–20cm；下层按当地根区和试验设计补采，不把示例深度当全国标准 |
| 可自动取得 | 多年逐日最高/最低/均温℃、降雨mm、短波辐射MJ/m²/day、ET0mm/day；自算ET0时再需要湿度、风速、气压等 | 水热风险、作物阶段、水分平衡、历史情景 | 现有Open-Meteo ERA5；如要求境内供应链，再申请气象局站点数据；站点与地块距离和海拔差需要记录 |
| 第二批 | 砂/粉/黏粒%、有效根深m、田间持水量与萎蔫点m³/m³、初始含水量、排水状况；盐渍风险地补EC及其测定方法 | 把累计降雨改成逐日根区可用水 | 分层检测、土壤数据库、传感器；经验推算的持水参数需注明估计来源 |
| 第二批 | 灌溉日期与水量mm或m³及对应面积、方式/效率、积水持续时间 | 取消“有灌溉就不缺水”的假设 | 水表、泵流量×时长、人工记录；传感器需安装深度和校准信息 |
| 第一批经济数据 | 各等级收购价、商品率、种苗/人工/租地/机械/灌溉/采收/运输费用，区分元/亩和元/kg | 可售收益、增量投入收益与盈亏平衡价 | 当地收购商报价、合同、收购单和经营台账 |
| 专项标定 | 不施肥、缺N、缺P、缺K、完整NPK等处理，带重复/区组、施肥量、薯块和茎叶干物质量及N/P/K含量 | 识别土壤固有供应、回收率、QUEFTS内部效率；单靠最终产量不能把这些参数分别识别出来 | 与农技站/农科院设计试验，优先索取既有原始试验表 |
| 后续增强 | 病虫草害发生期/严重度、灾害、冠层覆盖/遥感指数、实测生育阶段 | 季中修正和损失解释 | 现有照片/巡田体系及遥感数据；不直接把识别置信度换成减产比例 |

所有数值还需记录：来源、采集时间、单位、缺失/估计标志。N、P、K元素量与肥料标签N–P₂O₅–K₂O不能混用；总磷/总钾不能直接替代有效磷/速效钾；有机碳和有机质也不能无依据互换。化验浓度不等于整季可吸收供应。

第一轮可先争取一个目标地区、1–2个品种、30–50条完整“地块×季节”生产记录作为流程试点，尽量跨2–3季并包含低产/失败记录。这是采集起点，不是统计样本量结论或上线精度保证。以覆盖差异和独立验证表现决定是否扩大。只有生产台账时先校准产量与收益，不宣称已经标定了全部生理和养分参数。

最简生产记录字段：地块ID｜坐标｜季节｜品种｜面积及单位｜播期｜收获日期｜鲜薯重量｜商品薯重量｜肥料明细｜灌溉明细｜测土报告编号｜成本明细｜实际售价｜异常事件。测土、施肥、灌溉建议另表用地块ID＋季节关联，以保留多次事件。

## 7. 已核实的数据与研究入口

- 多年天气：Open-Meteo提供ERA5历史数据与所需逐日变量；可继续用于国内坐标，但供应商不是国内机构。[官方文档](https://open-meteo.com/en/docs/historical-weather-api)
- 国内站点：国家气象信息中心日值数据集是可申请核实的来源；本次没有完成账号权限、最新可下载年段与商业使用条件验证。[官方入口](https://m.data.cma.cn/data/detail/dataCode/SURF_CLI_CHN_MUL_DAY_V3.0.html)
- CSDLv2：2025年论文介绍90m、多层、含AN/AP/AK与不确定性信息的中国土壤产品，可评估为旧格网升级候选；土壤剖面仍主要来自1970–1980年代二普。版本更新不等于2025年实测。尚未实际下载或验证接入。[原始论文与数据链接](https://essd.copernicus.org/articles/17/517/2025/)
- 2010–2018国家土壤信息格网：提供pH、有机碳、容重、质地、全N/P/K等，可补物理性质；不能把全量养分当作现用的有效养分。[中科院南京土壤所数据目录](https://soildata.issas.ac.cn/lists/index/pid/1/order/down.html)
- 区域较新实测示例：山东禹城2007–2020年0–20cm耕层数据，含坐标、pH、全氮、有效磷、有效钾及方法说明；研究区为小麦—玉米轮作区，不能直接作为全国红薯数据使用。[原始数据论文](https://doi.org/10.3974/geodp.2025.01.12)
- AKILIMO实现可继续参考肥料产品组合、收益比较与离线预计算结构，但模型数据和地区参数需自行准备。[官方源码](https://github.com/IITA-AKILIMO/akilimo-recommendations)

## 8. 实施顺序与验收

第一轮：全球多年天气情景、评分拆分、页面简化、来源与缺失状态、方案对比；中国原功能继续保留。海外土壤先做iSDAsoil/SoilGrids样点与访问验证，按可取得字段逐步开放功能。先保留并清晰标注尚未校准的养分与产量参数。

第二轮：根据目标地区与品种审核甘薯参数、接入测土原始报告、实现逐日水分模块、真实肥料与价格；缺乏依据的参数不伪装成当地标准。

第三轮：回收实收记录，按地块和年份隔离训练与验证，比较地区历史均值等简单基线，报告MAE/RMSE、系统偏差及区间覆盖率；另评估施肥推荐的增量收益，避免只看亩产拟合好不好。

新增验证重点：相同累计雨量不同分布的水分反应、跨年播期和闰日、干鲜重/亩公顷/氧化物单位、N/P/K缺素响应、预算边界、多年区间可复算、缺数据提示、修改参数后旧结果状态、窄屏操作。QUEFTS还需要与上游R实现做固定样例数值对照，目前12项测试不包含这种对照。
