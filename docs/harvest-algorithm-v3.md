# AI收成预测 Beta 3：算法、数据与更新

实现：`harvest-model.js`（纯计算）、`harvest.js`（界面和数据接入）、`scripts/calibrate-harvest.js`（离线校准）。算法版本 `harvest-beta-3.0.0`，参数版本 `tubers-beta-2026-09-23`。

## 使用顺序

地图选点 → 点击“分析这个位置” → 右侧摘要 → 展开完整分析。种植条件默认折叠；地图可以展开，按 Esc 收起。改坐标、作物或投入后，旧结果标记失效，重新计算后才能导出。

主网站沿用原来的 `?page=harvest` 页面和受保护的国内土壤接口。独立 `harvest-demo.html` 默认人工天气及示例养分，专供交互体验；主网站默认真实历史天气和国内格网。不会把天气请求失败自动替换为人工数据。

支持红薯、木薯。品种名称用于记录与校准分组，填写名称不会生成该品种参数。海外可读取全球历史天气；国内格网范围外自动改为气候初筛，补齐养分供应后才计算产量和经济结果。

## 1. 年景集合

按选定播种月日、生育天数构造最近 5、10、20 个完整历史生长季，每个季节单独逐日模拟。历史上限是“播种日期与计算日期较早者”的前一完整日历年，跨年的季节须整体结束在该上限内，避免回算时使用播种后的年景。2 月 29 日在非闰年映射为 2 月 28 日并记录。

数据使用 Open-Meteo ERA5：日均温、最低温、降水、FAO ET0、短波辐射。必需变量缺一天就排除整个年景并报告，不以 0 补值；在线分析至少需要 3 个完整年景。P10/P50/P90 是这些历史情景的经验分位数，不是未来预测置信区间，也不包括全部参数误差和价格风险。未接入季节气候预报。

来源：[Open-Meteo 历史天气接口](https://open-meteo.com/en/docs/historical-weather-api)。

## 2. 逐日土壤水分

根区可用容量 `TAW = 1000 × (田间持水量 − 萎蔫点) × 根深`，单位 mm。根深由 0.15m 随生育进度增长；新增土层带入的水量单独记账。

逐日收支：

`期末可用水 = 期初水 + 新根层带入水 + 降水 + 灌溉 − 径流 − 深层排水 − 实际蒸散`

降雨入渗受到质地对应的假设日入渗上限与径流比例限制。超过根区容量的水作为深层排水。`ETc = ET0 × Kc`；允许耗水比例按 `p + 0.04 × (5 − ETc)` 调整，限制在 0.1–0.8；水分胁迫系数 `Ks = min(1, 可用水 / [TAW × (1−p)])`，实际耗水还受可用存水限制。

自动补灌同时受单日和整季水量上限限制。纯计算接口也接受实测逐日灌溉序列。输出逐日水量、缺水天数（Ks<0.5）、最长连续缺水、阶段汇总与质量守恒误差。

依据：[FAO-56 第6章 Kc](https://www.fao.org/4/X0490E/x0490e0b.htm)、[第8章根区水分](https://www.fao.org/4/X0490E/x0490e0e.htm)。本版采用简化单作物系数，不是完整土壤水动力模型。

| 参数 | 红薯 | 木薯 | 依据/状态 |
|---|---:|---:|---|
| Kc 初期/中期/末期 | 0.5/1.15/0.65 | 0.3/0.8/0.3 | FAO-56；木薯第一年 |
| 默认根深 m | 1.0 | 0.6 | 在 FAO 表列范围内，田块可改 |
| 允许耗水比例 | 0.65 | 0.35 | FAO-56 |
| 生育阶段相对长度 | 20/30/60/40 | 20/40/90/60 | FAO 示例比例；转为积温进度 |
| 基温 °C | 10 | 12 | Beta 假设 |
| 成熟积温 °C·d | 2400 | 4500 | Beta 假设，待品种标定 |
| 鲜重潜力 kg/ha | 36000 | 45000 | Beta 上限，非当地潜力测定 |
| 干物质比例 | 0.25 | 0.35 | 通用参数，需实测 |

质地默认 FC/WP、入渗与径流系数、初始含水 60% 都是假设。算法接口支持实际 FC/WP；界面当前可修改质地、根深、初始水量。

## 3. 生长与养分限制

每日有效积温决定生育进度；进度增量乘以阶段权重、温度响应、辐射响应和水分胁迫，再考虑霜冻存活和积水折减，累积成生长比例。鲜重潜力 × 干物质比例 × 生长比例 × pH 响应得到水热限制干物质上限。

阶段权重、短波辐射除以18的响应、霜冻损失、积水阈值和 pH 折减均为透明的 Beta 规则。**没有实现完整 LINTUL 的冠层、光截获、呼吸和碳分配过程；不能声称已复刻 AKILIMO 的当地验证精度。** AKILIMO 上游水限制脚本会读取已有的地区模型结果，本项目没有那些标定数据。

养分使用 [AKILIMO `R/quefts.R`](https://github.com/IITA-AKILIMO/akilimo-recommendations/blob/main/R/quefts.R) 的 JS 移植：结合土壤供应与肥料回收，计算 N/P/K 两两约束的吸收和干物质产量，最终受水热上限约束。干物质除以干物质比例得到鲜重；每公顷除以15得到每亩。

肥料标签按 N–P₂O₅–K₂O，P₂O₅ ×0.4364 转为 P，K₂O ×0.8301 转为 K，再乘作物回收系数。已有同配方肥料与新增肥料共同进入供应；已有投入费用应包含在基础成本中。当前未模拟施肥时期、盐害、有机肥释放或病虫草害。

木薯养分参数沿用报告中的 AKILIMO 来源；**红薯仍使用报告中的马铃薯代理参数**。候选红薯 QUEFTS 文献在干重/鲜重口径核实前没有强行替换；这是当前准确度的重要限制。

国内土壤在 `server-data/china-soil/`（忽略 Git），只包含 0–4.5cm 表层历史背景。换算为“情景供应”：`浓度 mg/kg × 容重 g/cm³ × 厚度 m ×10 × 假设利用比例`。不把表层数值外推至完整根区；这也不能替代整季可吸收供应的田间测定。总氮、总磷或不同提取法测出的磷钾不能直接互换。

## 4. 收益比较

在预算和最大用量内，以 1kg/亩步长枚举新增肥料，另包括精确预算边界。每个候选量在每个年景下计算：

`商品产量 = 鲜重 × 商品率`

`结余 = 商品产量 × 售价 − 基础成本 − 新增肥料成本 − 鲜重 × 采收运输等变动费用`

保守模式比较情景 P10 结余；均衡模式比较平均结余。输出较优候选、不新增肥料、中档投入、盈亏平衡售价，以及情景中亏损的占比。该占比不是未来亏损概率；较优候选不是专业施肥处方。币种切换只改金额标签，不自动换汇。

气候分数是温度/成熟、水分、霜冻存活规则指标的最小值，非种植成功概率。养分单列，避免良好气候掩盖养分短缺。气候初筛不生成产量和收益。

## 5. 后续怎样变准

第一步先保存播种前预测 JSON，包含算法/参数版本、输入、数据来源和每个年景结果。收获后记录稳定地块 ID、真实面积和鲜重，核对实际管理是否与预测一致。如果实际肥料、水量或品种改变，应记录偏差并排除不匹配样本或按真实管理重新组织研究数据；不能拿推荐方案产量与另一种实际管理盲目拟合。

界面可导出实收记录，但尚无历史记录数据库。后续可从保存的预测 JSON 整理实收记录；当前页面的收获录入只针对当前预测。将同作物、同品种的 JSON 记录合并成数组，并把 `split` 从 `unassigned` 分为 `train` / `validation`：

```sh
node scripts/calibrate-harvest.js observations.json candidate.json
```

记录必须包含：`id, fieldId, split, seasonYear, harvestDate, crop, variety, lat, lng, observedFreshKgHa`，以及 `prediction.engineVersion, parameterVersion, generatedAt, calibrationId:null, sourceKind:"history", rawYears:[{freshKgHa,waterLimitKgHa}]`。预测须在收获前生成；不接受人工天气、旧版本或已经校准过的预测。

训练与验证不得共享地块，验证年份晚于全部训练年份。工具只拟合 0.5–1.5 的整体鲜重偏差系数，逐年结果仍不能超过水热上限；这不是对生理参数的完整标定。验证报告提供 MAE、RMSE、平均偏差、样本数量与原始数据 SHA256。

至少10条训练、5条验证、各3个地块，且独立验证 MAE 改善、RMSE 不变差，才会标记 `eligibleForReview`。这是工程审核门槛，不是统计精度保证。输出永远为 `candidate`。人工审核代表性、误差和空间范围后，才设置为 `approved` 并导入界面；包受版本、作物、品种和样本坐标包围框约束。当前为本机研究工具，没有签名和中心审批服务，不能将 JSON 状态当成可信认证。

进一步更新：先用多年多点实收校正偏差；再用独立试验估计成熟积温、干物质比例、产量潜力和养分回收；有足够逐日土壤水分后校正 FC/WP、根深和入渗；最终替换简化生长模块。每次参数或算法变动递增版本，用固定独立验证集比较 MAE/RMSE/偏差及分地区表现，保留旧版以便回退。不要反复挑同一验证集上的最优结果并称为独立验证。

## 6. 优先收集的数据

| 优先级 | 数据 | 用途 |
|---|---|---|
| 最高 | 稳定地块ID、经纬度、作物/品种、种植和收获日期、实际面积、鲜薯重量 | 核实预测误差，建立可追溯实收样本 |
| 最高 | 实施的肥料配方、用量、时期，灌溉水量/日期 | 匹配实际管理与预测条件 |
| 高 | 土壤采样时间/深度、容重、质地、pH、有效 N/P/K及检测方法 | 替换历史格网与供应假设 |
| 高 | 零肥、缺N/缺P/缺K和充分施肥对照，植株养分吸收 | 标定本底供应与 QUEFTS，不能仅靠化验浓度反推 |
| 高 | 商品率、干物质比例、售价、基础成本和采收运输成本 | 统一鲜/干重口径和收益核算 |
| 后续 | FC/WP、逐层土壤水分、根深、物候、病虫害/积水记录 | 校正水分和生长模型，解释异常 |

全球天气已接入。非洲可评估 iSDAsoil；全球可评估 SoilGrids 的质地/容重/pH 等。它们的养分定义、土层、单位需分别映射；未下载或接入海外土壤。候选来源、国内更新数据和获取限制见 `harvest-optimization-review-2026-09-23.md`。

## 验证范围

Node 测试覆盖逐日水分守恒、降雨时序差异、灌溉上限、成熟与低温、零养分、真实情景分位数、跨年/闰年/历史时间边界、缺测排除、单位/币种尺度及校准隔离。国内读取另有 Python 测试。测试通过证明实现满足这些约束，不等于田间精度验证；未运行原生 R 的跨语言数值验证。
